一、3 条任务流低保真原型草图

原型说明：纸面线框（Lo-Fi Wireframe），灰块代表文字、叉框代表图片占位、圆点代表语音；每条任务流标注触发语与记忆/提示时机。测试设备为手机端对话式智能体。
任务流 ①（简单）· 图文问答：「帮我对比两款产品的参数」 EXPERIMENT A · STANFORD CS147 (A5)

触发语示例：「对比 A 和 B 的价格」 → 记忆触发时机：任务完成后询问「要把结果存成常用对比模板吗？」

目标：在接入复杂多模态工作流前，通过先导可用性测试（Pilot Usability Testing）提前发现交互断点。
任务：针对智能体的「图文 / 语音 / 卡片」多模态交互，绘制 3 个任务流（简单 / 中等 / 复杂）的低保真原型；邀请 2 名同学完成走查测试，记录关键事件日志（Critical Incidents）并按 0–4 级严重度打分，据此优化记忆触发时机或提示语。

二、先导可用性测试 · 关键事件日志与 0–4 级严重度评分

测试设置：参与者 P1、P2（2 名同学）；方法为出声思维走查（Think-aloud Walkthrough），每人完成上述 3 条任务流；观察员记录关键事件（Critical Incidents）并按 Nielsen 0–4 级独立打分，取两人较高值作为该事件严重度。严重度含义：0=不是问题；1=外观/小瑕疵；2=轻微问题，偶尔发生；3=主要问题，阻碍任务但可绕过；4=灾难问题，无法完成任务。
编号任务流参与者关键事件描述（Critical Incident）严重度观察记录 / 影响
CI-01① 图文问答P1检索加载态仅显示三个跳动的点，P1 连续等待 12 秒后认为「卡死了」，试图退出重进。2缺少进度提示与可取消操作；多模态生成耗时长，需明确反馈剩余步骤。
CI-02① 图文问答P2结果卡片中的价格表图文混排，P2 一度把「图片里的旧款价格」误当作结论，忽略下方文字结论。2结论行未突出；应在卡片顶部放置一句结论摘要（信息层级问题）。
CI-03② 语音指令P1 / P2松开麦克风后语音直接执行：P1 把「上周」识别成「上上周」，图表生成后才发觉；P2 无效执行一次后重说。3语音转文字无确认环节，错误难以撤回；两人均触发，属主要可用性断点 → 进入优化对比。
CI-04② 语音指令P1波形动画持续时 P1 不确定系统是否在收音，重复半句话导致指令被截断。1收音状态反馈不够明确（轻微，视觉提示即可解决）。
CI-05② 语音指令P2图表卡片导出按钮与「每周自动生成」并列，P2 误触订阅，找不到取消入口。2高频操作与低频设置未区分层级；订阅后缺少立即确认 Toast。
CI-06③ 客服工单P1 / P2上传截图＋语音后，系统无「已识别订单号 #8821」的确认信息，两位参与者均不确定附件是否提交成功。3多模态输入缺少结构化回显；主管 Agent 的识别结果应即时回显并允许修改。
CI-07③ 客服工单P1派单进度页只显示百分比，P1 看不懂「订单 Agent / 促销 Agent」在做什么，等待 40 秒时想放弃。2多智能体协作过程对用户不透明；需用一步一行的白话进度代替百分比。
CI-08③ 客服工单P2「结论卡片」直接给出补偿方案，P2 未细读规则解释就点「转人工」，随后自己发现答案又返回。1卡片信息密度偏高；关键动作建议放在结论首行并弱化次要解释。
CI-09③ 客服工单P1 / P2转人工后聊天上下文仅显示「已同步」，两位参与者都追问「客服能看到我的截图吗」。2人工接管的上下文同步应可视化（列出已带入截图、语音转写与结论）。

三、1 处交互优化前后对比（针对 CI-03 · 严重度 3）

优化对象：语音指令的「记忆触发时机 / 提示语」。问题根源：语音松手即执行，转写错误无法在执行前拦截。优化策略：在「语音 → 执行」之间插入转写确认步骤，并提供历史同类报告的记忆快捷入口。
✗ 优化前
流程：长按说话 → 松手 → 立即执行 → 生成图表卡片
提示语：「已收到指令」
实测后果：①「上周」被识别为「上上周」，图表方向性错误，用户须整段重来（P1）；② 无效执行浪费一次生成（P2）；③ 无机会修正个别词语，用户只能放弃语音改打字。
违反启发式：错误预防（Error Prevention）、用户控制与自由。
✓ 优化后
流程：长按说话 → 松手 → 转写确认页（可点按修改文字） → 「确认执行 / 重新说」 → 生成图表卡片
提示语：「我听到的是：'把上周销量画成柱状图，按天分组发给我'（点击可修改）」＋ 记忆触发：「🕘 上次同类报告：11 月第 2 周，一键套用相同设置」
设计要点：① 把不可逆操作改为可逆确认；② 修改文字比重说整句成本低；③ 利用任务记忆提供快捷入口，减少重复描述。
回测结果：P1、P2 复测均一次性完成任务，平均用时由 86s 降至 52s，CI-03 未再复现。

注：以上测试者、事件、评分与回测用时均为模拟数据，仅演示先导测试与严重度分级方法。

实验 B · 多智能体架构设计（两张思维导图）

图 1 · 电商客服多智能体协作架构图（思维导图式）

实验目标：从「只写单条提示词（Prompt）」升级为「设计多智能体组织架构（搭组织）」——理解并套用「主管 Agent + 专家 Agent」架构，掌握工作流核心组件（选择器 / 批处理节点 / 子工作流），并完成架构流程图、路由规则与场景映射三项实操产出。
交付形式：图 1 · 电商客服多智能体协作架构导图；图 2 · 主管 Agent 路由规则与场景映射导图（可佐以 If/Then 规则表落地）。
读图要点：中心为整体系统；分支按「输入 → 派单 → 专家处理 → 路由 → 人工兜底 → 结果输出」组织，覆盖全部节点：主管 Agent、订单 Agent、促销 Agent、选择器、人工介入，并标注子工作流与批处理节点的位置。
阅读方式：中心系统 → 主管 Agent 接单派单（虚线）→ 专家 Agent 组并行处理 → 选择器路由「能答 / 转人工」→ 人工介入兜底 → 卡片结果输出。

虚线 = 主管 Agent 的派单 / 路由关系；实线 = 导图分支关系。工具实现：Coze / Dify / FastGPT 均可拖拽搭建。

落地表格 · 主管 Agent 路由规则表（与图 2 对应）

编号If（用户问题特征）Then（路由至）说明
R1提问包含「物流 / 发货 / 退换货 / 订单状态」订单专家 Agent走子工作流：查单 → 核销 → 规则匹配
R2提问包含「优惠 / 满减 / 券 / 折扣」促销 Agent知识库 RAG 检索促销规则后作答
R3同一问题 AI 连续 2 次未能解决人工介入兜底机制，上下文与截图一并同步
R4检测到情绪激动、投诉、涉资金安全人工介入（优先级最高）决策权留人类，AI 仅做摘要辅助
R5意图不明 / 多意图混杂主管 Agent 澄清追问先追问确认类型，再按 R1–R4 派单
场景映射说明：多智能体 = 现实里「科室协作」的软件映射——不要试图做一个万能 AI，而是让一个「主管 AI」接单，按问题类型（订单、促销、人工）分发给对应的「专家 AI」。相比单一全能体：① 每个专家上下文更专注、答案更准；② 出错可隔离定位，不会牵一发动全身；③ 新业务只需新增一个专家节点，可扩展、易维护。
主管 Agent 提示词示例：「你是客服主管。判断用户问题类型后仅派单给一个专家，不确定时先澄清；检测到投诉或两次未解决立即转人工。」

注：本页路由规则与场景映射为课程实验模拟设计，非真实系统配置。
